### MVP1 and the Godot port

Combat needs one Opus design seat first: enemy state machines, the health model that coexists with one-hit falls, and validator treatment of enemies. After that it follows the M2–M3 pattern, with gamer-pro on the core and cursor on views. The Godot port suits gamer-pro well, because it has GDScript, golden runners and inventory docs behind it. Port `Vec3.gd` (float64 fields, never `Vector3`), `Aabb.gd`, `Hook.gd`, `Rope.gd`, `Rules.gd`, `HeroBrain.gd`, `Sim.gd` and `Replay.gd` one file per run, with `GoldenRunner.gd` running the TS traces through `godot --headless` as the controller-rung gate. That is about 10–12 gamer-pro runs. Add `LevelLoader.gd` and a cursor-scale adapter rewrite (SpringArm, InputMap, Control UI). Estimate 8–14 wall days, against the plan's "1–2 weeks", and only if MVP0 per-tick quantization (finding #4) landed first. `ZiplineAbility` is a further 3–5 days once the shooter's host contract exists.
